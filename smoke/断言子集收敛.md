## 1. 双工具兼容矩阵（实测）

表格列说明：**iverilog** = `iverilog -g2012` 编译；**yosys(-formal)** = `yosys -p "read -sv -formal <f>; prep -top t"`（sby 等价读取路径）；**yosys(默认)** = `yosys -p "read -sv <f>; prep -top t"`（sby `[script] read -sv` 的实际默认路径，实测 sby 不会自动附加 `-formal`）。✓ = 编译通过，✗ = 编译失败（iverilog 返回码非 0 / yosys ERROR），√cell = 通过且生成 `$assert`/`$assume` 形式化单元。

| # | 语法形式 | iverilog 12 | yosys(-formal) | yosys(默认) | 结论 |
|---| --- | --- | --- | --- | --- |
| a1 | `always @(posedge clk) assert (expr);` | ✓ | ✓ √cell | ✓ √cell | **安全子集** |
| a2 | `always @(posedge clk) if (en) assert (expr);` | ✓ | ✓ √cell | ✓ √cell | **安全子集**（条件门控） |
| a3 | 打拍跨周期：`always @(posedge clk) begin en_d<=en; cnt_d<=cnt; if(en_d) assert(cnt==cnt_d+1); end` | ✓ | ✓ √cell | ✓ √cell | **安全子集**（跨周期核心） |
| b1 | `assert property (expr);`（无时钟） | ✗ | ✓ √cell | ✓ √cell | 仅 yosys，非双工具子集 |
| b2 | `assert property (@(posedge clk) expr);` | ✗ | ✗ | ✗ | 双工具均不可用 |
| b3 | `assert property (@(posedge clk) disable iff (!rst_n) expr);` | ✗ | ✗ | ✗ | 双工具均不可用 |
| c1 | `assert property (@(posedge clk) $past(en)==...);` | ✗ | ✗ | ✗ | 双工具均不可用 |
| c2 | `assert property (@(posedge clk) $rose(en) \|-> ...);` | ✗(rc=3) | ✗ | ✗ | 双工具均不可用 |
| c3 | `assert property ($past(en)==...);`（无时钟） | ✗ | ✗ | ✗ | 双工具均不可用 |
| c4 | `always @(posedge clk) assert ($rose(en));`（immediate 语境） | ✓（语义存疑） | ✓（隐式时钟展开 √cell） | ✓ | **编译兼容但语义不统一，不推荐** |
| d1 | `initial $fatal(1, "msg");` | ✓ | ✗ | ✗ | 仿真专用（iverilog） |
| d2 | `always @(posedge clk) if (en) $fatal(1, "msg");` | ✓ | ✗ | ✗ | 仿真专用（iverilog） |
| e1 | `assume property (@(posedge clk) expr);` | ✗ | ✗ | ✗ | 双工具均不可用 |
| e2 | `assume property (expr);`（无时钟） | ✗ | ✓ √cell($assume) | ✓ | 仅 yosys |
| e3 | `always @(posedge clk) assume (expr);`（immediate） | ✓ | ✓ √cell($assume) | ✓ | **安全子集**（环境约束） |

**关键事实**
- iverilog 12 对 `assert property` **任何形式**（含无时钟）均编译失败；`assume property` 同样失败。
- yosys 0.33 对带时钟/disable iff/|->/##/$past 的 concurrent 形式报 `unexpected '@'` / `unexpected '>'`（-formal 与否无差别）。
- yosys 对 **immediate `assert`/`assume`**（含 always 块内条件门控）无论是否 `-formal` 都生成 `$assert`/`$assume` 单元 → sby 默认 `read -sv` 也可用，但建议显式 `read -sv -formal`（语义明确，与 sby 官方模板 `read -formal` 一致）。
- 原始诊断结果留档：`smoke/.svatest/matrix.txt`（diag_assert_v3.sh 自动生成，目录可重建）。

## 2. 推荐安全子集清单

### 2.1 核心写法（5 条保底）

1. **immediate assert（基础）**
   ```systemverilog
   always @(posedge clk) assert (cnt != 2'd3);
   ```
2. **immediate assert + if 条件门控**（yosys 将其生成为 `$assert` 单元的 EN 使能端）
   ```systemverilog
   always @(posedge clk) if (en) assert (cnt == 2'd1);
   ```
3. **打拍实现跨周期性质**（推荐主模式，替代 `|-> ##1 $past`）
   ```systemverilog
   reg        en_d;
   reg  [1:0] cnt_d;
   always @(posedge clk) begin
     if (!rst_n) en_d <= 1'b0;
     else begin
       en_d  <= en;      // 打拍：下一拍可见
       cnt_d <= cnt;     // 打拍：记录使能拍计数值
       if (en_d) assert (cnt == cnt_d + 1'b1);  // 检查：本拍 cnt == 上一拍 cnt + 1
     end
   end
   ```
4. **immediate assume（环境约束）**
   ```systemverilog
   always @(posedge clk) if (valid) assume (data < 8'h40);
   ```
5. **formal 初始状态初始化**（配合断言，避免"任意初始状态"空洞反例）
   ```systemverilog
   initial begin cnt = 0; en_d = 0; cnt_d = 0; end
   ```
   yosys 提取为 init 属性；iverilog 仿真中与复位时序兼容。

### 2.2 使用限制（Gate-1 收敛结论）

- **禁用**：`assert property` / `assume property`（带时钟、无时钟、disable iff、|->、##n、$past、$rose 一切 concurrent 形式）——iverilog 12 全失败。
- **禁用**：concurrent 语境的 `$rose/$fell/$past`（双工具失败）。跨周期一律用**寄存器打拍**替代。
- **慎用**：immediate 语境的 `$rose(...)`（c4）：双工具编译通过、yosys 按隐式时钟展开成 `$dff+$logic_and+$logic_not`，但 iverilog 侧语义无保证 → 不推荐进安全子集，确需边沿检测请打拍比较 `en && !en_d`。
- **语义提示**：immediate assert 写在 `always @(posedge clk)` 内，表达式读取的是**本拍更新前**（非阻塞赋值前）的值，故"上一拍条件成立 → 本拍检查结果"天然等价于跨周期断言，这正是安全子集能替代 concurrent SVA 的原因。
- **变量作用域**：断言表达式只能引用本模块可见信号，不能引用其他模块内部信号；跨模块性质需在目标模块内部断言。

## 3. $fatal 双实现说明（iverilog 侧）

- iverilog 12 的 `$fatal` **首个参数必须是数字 finish number**：`$fatal(1, "msg")`；写成 `$fatal("msg")` 会报 `ERROR: $fatal's finish number must be numeric`（本轮已踩坑并修正 tb）。
- 两种可用语境（编译均通过，运行即终止仿真并以非零码退出）：
  - `initial` 块：tb 中显式检查失败路径上报（`if (cnt !== 2'd0) $fatal(1, "FAIL: ...")`）；
  - `always` 块（含时序块内条件触发）：同样可用。
- yosys `read_verilog` 对 `$fatal` 不支持（d1/d2 均编译失败）→ **$fatal 纯仿真侧机制**，与 formal 断言互补：弱 tb 用 `$display("PASS...")/$fatal` 判定，缺陷检出交给 sby 断言。
- 规范约定（L3 样本）：tb 成功路径 `$display("PASS: ...")` + `$finish`；失败路径 `$fatal(1, "FAIL: ...")`；断言失败交给 formal。

## 4. 对方案 6.4 候选表的修正对照

| 方案 6.4 候选 | 原标注 | Gate-1 实测修正 |
| --- | --- | --- |
| `assert (expr);` immediate | ✓ ✓ | **确认**；补充"if 条件门控"可用，yosys 生成 EN 门控 `$assert` cell |
| `assume (expr);` | ✓ ✓ | **确认** immediate assume 双工具兼容，生成 `$assume` cell |
| `assert property (@(posedge clk) a);` | iverilog ✓ / yosys 部分 | **删除**：iverilog 12 实测 ✗（编译失败）；yosys ✗（unexpected '@'） |
| `$rose/$fell/$past` | iverilog ✓ / yosys 待实测 | **删除**：concurrent 语境双工具 ✗；immediate 语境仅 `$rose` 编译兼容但语义不统一（c4），不推荐 |
| `\|->` / `##1` 简单 sequence | 部分 / 待实测 | **删除**：双工具均 ✗ |
| （新增）打拍跨周期模式 | — | **加入安全子集**：`en_d<=en; cnt_d<=cnt; if(en_d) assert(cnt==cnt_d+1)`，已验证可替代 `\|-> ##1 $past` 类性质 |
| （新增）无时钟 `assert property (expr)` | — | 仅 yosys ✓（生成 `$assert` cell），iverilog ✗ → 列为 yosys-only 扩展，不入双工具子集 |
| （新增）initial 初始化寄存器 | — | 加入：为 formal 提供合法初值，避免空洞反例（见 2.1-5） |

## 6. 工具链环境与 sby 运行说明

- sby 的 `[script] read -sv <f>` 实测**不自动附加 `-formal`**（sby_core 源码确认；其初始化模板为 `read -formal`）。本项目 .sby 一律显式写 `read -sv -formal`。
- 本机缺外部 SMT solver（yices/z3/boolector 均未装），`smtbmc` 默认找 `yices-smt2` 失败；已 `pip3 install --user --break-system-packages z3-solver`（`~/.local/bin/z3`），并通过包装脚本注入：
  - `smoke/yosys-smtbmc-z3.sh`：`exec /usr/bin/yosys-smtbmc -s z3 "$@"`；
  - `smoke/run_sby.sh`：统一入口，export `PATH`（z3）与 `SMTBMC`（包装脚本）后执行 sby。
- 引擎备选实测：`abc bmc3`（无需外部 solver）在 sby 0.33 + 新版 yosys-abc 组合下崩溃（`KeyError: 'asserts'`，cex ywa 格式不兼容），弃用；正式通道用 `smtbmc` + z3。
- counter.sby 调整说明：`read -sv` → `read -sv -formal`（语义明确）；depth 8 → 10（反例约 6 拍，留 4 拍裕量）；引擎 smtbmc（配 z3）。
