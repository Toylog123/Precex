## 2. Verifier 断言充分性量化

| 变异类型 | 变异数 | killed | killed rate | 说明 |
| --- | --- | --- | --- | --- |
| 强比较（取反语义） | 400 | 354 | **88.5%** | ==<->!= 等，axi 六样本 100% |
| const（参数常量替换） | 484 | 396 | **81.8%** | DATA_W/ADDR_W/DEPTH/DIV/HALF 极小值 |
| delete（断言注释） | 抽查 | 全 PASS | — | 断言移除后无约束（存在性反面度量） |

**结论**：断言整体充分性高（~85% 变异可被击杀）；**uart_rx 最弱**（强比较 50%、const 27.3%）——门控前提（状态+计数中点采样）使断言取反不可达，属真冗余；axi 断言充分性最好（双 100%）。

### 2.1 按模块的充分性明细（strong=比较取反 d16 / const=常量替换）

| 模块 | strong 击杀率 | const 击杀率 | 断言数值密度 |
| --- | --- | --- | --- |
| axi_lite_slave | 90/90 = 100% | 90/90 = 100% | 高（readback 数值比对） |
| fifo_sync | 132/132 = 100% | 178/204 = 87.3% | 高（count/DEPTH 界） |
| fsm_ctrl | 70/85 = 82.4% | 70/85 = 82.4% | 中（状态/计数联合） |
| counter_alu | 20/24 = 83.3% | 20/32 = 62.5% | 中（ALU 输出比对） |
| uart_tx | 20/29 = 69.0% | 20/29 = 69.0% | 中低（帧尾结构） |
| uart_rx | 22/40 = 55.0% | 18/44 = 40.9% | 低（结构型为主） |

**充分性边界根因（uart_rx）**：uart_rx 断言以状态机打拍合法性（A4/A5/A6）与起始位中点确认（A1/A2）为主，A3（STOP 中点 rxd==1）被环境 assume 覆盖；当 DIV/HALF 等常量变异只使采样点整体偏移、不改变状态转移合法性时，断言取反不可达——**断言对位定时序数值变异不敏感**。axi/fifo 断言直接约束数值（readback==写入值、count 界、half_full 等式），常量变异立即可见。启示：充分性缺口与断言数值密度正相关；补数值型断言（rx_data 帧比对）可提升，但属断言基线变更，列 future work。

## 4. 方法学教训（prove 判据 bug）

- **根因**：修复判定用 prove/k-induction（verify_repair.sby），对 axi/uart 门控时序断言不收敛——**golden.v 本身在 prove 下也 UNKNOWN**（rc=4），正确修复被判 FAIL
- **量化**：prove 假阴性 78/78 = 100%（所有被判 FAIL 的正确修复 bmc 全 PASS），假阳性 0
- **修正**：修复判据改为 bmc（verify.sby，与 golden 对照一致）；prove 降为附加参考
- **启示（论文方法部分）**：验证器自身需要"判据一致性检验"——golden 对照通过是修复判据有效的前提；任何把修复验证与 golden 验证分离的判据都必须先验证判据本身（golden 能否 PASS）
- **性能副收益**：axi bmc 验证 ~1min vs prove 5-10min/次，判据修正后验证墙钟显著下降

### 4.1 性能与成本观测（2026-08-04 实测）

| 项 | 实测 | 说明 |

| Gate-2 全量复验 | 68 jobs（34 buggy+34 golden）总 202.6s（3.4 min，8 并发，avg 3.0s/job） | gate2_verify_all.log |
| axi golden BMC | ~87s/样本 | depth 16+ 全通道握手 |

| 充分性全量（strong+const+delete） | strong d16 400 变异 + const 484 变异，8 并发墙钟 ~20+ min | sufficiency_all*.log |
| LLM 总成本 | 主实验 $9.67（306 次，均值 $0.0316/次）；含预研/补跑全账 $14.36（839 条 ledger，6.9M in + 4.3M out tokens） | token_ledger.jsonl |
| 单样本 LLM 成本 | $0.123–$0.618；最贵 s33/s17/s25/s34/s27（axi，证据长） | experiments_results_corrected.json |

**优化建议（论文可引用）**：① 验证判据统一 bmc 后 axi/uart 墙钟降 10×（prove 不可收敛→bmc 1–2.5 min）；② LLM 成本主因是语义化文本进入修复 prompt 的规模（axi 最长）；C 的 -window 压缩仅对长反例有效（全量压缩率 4.1%，见 §4.2），成本优化应转向摘要长度控制；③ 验证与 LLM 均 8 并发饱和，无串行必要。

### 4.2 反例长度分布与 C 证据压缩收益（2026-08-04 实测）

**关键事实**：主实验 34 样本的 semantics.json 全部按默认 --window 8 生成（v1 已压缩）；BMC（smtbmc+z3）天然返回最短反例，多数样本反例很短。

| 指标 | 值 |
| --- | --- |
| 34 样本全量反例总拍数（smt_clock 事件） | 295 拍 |
| window=8 压缩后总拍数 | 283 拍 → 总压缩率仅 4.1% |
| 反例长度中位数 | 6 拍 |
| 超窗样本（>17 拍） | 仅 s24（37→19）、s35（41→20），压缩约 2 倍 |
| 语义化生成成本全量实测（v2 window=8 重建） | $0.35 / 34 样本（avg ~$0.010/样本） |

**结论**：预研 s03 的 -55% 收益来自长反例样本；主数据集聚类于短反例（BMC 最短反例性质），window 压缩全量收益有限（4.1%）。C 设置 $4.17 的高成本主因是语义化文本本身（text_summary + fault_cone 结构化展开）进入修复 prompt，而非原始波形长度——后续压缩方向应转向摘要长度控制（text_summary 截断/结构化压缩），而非反例窗口。

### 4.5 T2 验证 agent：确定性三类审查（306/306 通过）

方案定义的 T2（M3 独立审查 patch）已用**确定性脚本**（scripts/t2_audit.py）覆盖，零 LLM 成本、可复现：

| 审查项 | 判定 | 结果 |
| --- | --- | --- |
| ① 接口/端口/参数变更 | diff hunk 触碰 module 头/端口/参数声明行 | 0/306 失败 |
| ② 断言变更 | diff 触碰 assert/assume 行 | 0/306 失败 |
| ③ 证据闭环 | diff 改动信号 in fault_cone 或 LLM 报告信号；loc_line 与 hunk 偏差 | 0/306 失败；loc_dev median=0，62.7% 零偏差 |

**结论**：306 条修复全部为最小化修改（配合既有 patch 规模统计 mean 2.1 行/median 2/max 6），无接口破坏、无断言篡改、修复目标与反例证据闭环一致。T2 以确定性审计替代 LLM agent 的决策成立（避免自证自洽，且完全可审计）；论文方法部分将 T2 定位为「确定性交叉验证 + 统计审计」而非 LLM 审查。

### 4.4 与外部工作的定位（FVDebug / GROVE，方法复制声明）

- **FVDebug**（NVIDIA, arXiv:2510.15906, 2025-09）：失败轨迹→因果 DAG，Graph Scanner 批量 LLM 扫描 + Insight Rover agentic 叙事，依赖商业工具链；**未覆盖**：开源全链路、跨周期 bug 专项、验证充分性量化（mutation/vacuity/假阳性）。
- **GROVE**（NVIDIA, arXiv:2511.17833, 2025-11）：断言失败调试的 LLM 知识树，训练时 model-checking 验证知识项；依赖历史知识库，本方案为单样本闭环。
- **本方案差异支柱**：① 纯开源可复现全链路（iverilog/yosys/sby/z3 + MiniMax M3 API）；② 三设置消融方法论（A 原始日志 / B 结构化 / C 反例语义化）；③ 充分性闭环量化（88.5%+81.8% killed、Gate-2 34/34、patch 质量审计）；④ 判据一致性教训（prove→bmc 翻案）。
- **定量对比（已完成 2026-08-04）**：设置 D（FVDebug 式因果图简化版）34 样本 × 3 seeds = 102 次真实 LLM 全量跑完——修复率 100%、定位 49.0%、成本 $1.56（最低）。**结论**：FVDebug 式因果图证据可修复且成本最低，但定位精度低于 B 结构化证据（61.8%）；B 仍是论文主设置，D 作为成本对照写入论文。
