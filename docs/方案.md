## 1. 项目概述

**目标**：3 个月内（2026-08 → 2026-10）构建一个**以形式反例为最高置信证据源**的综合前 RTL 缺陷定位与修复智能体，产出可发表论文、BugBench-PS 数据集与开源工具链。

**定案配置**：

| 项 | 定案 |
| --- | --- |
| LLM | MiniMax M3 API（OpenAI 兼容端点，1M 上下文，原生多模态，thinking，预算不限） |
| 工具链 | iverilog 12 / verilator 5.020 / yosys 0.33 / SymbiYosys（sby），全开源 |
| 人力/时间 | 单人 + 智能体自动化管线，13 周并行里程碑 |
| 差异化三支柱 | 开源全链路 ／ 三设置消融方法论（A/B/C）／ 跨周期专项 + 验证充分性量化 |

## 2. 背景与问题

### 2.1 失败证据层级
| 层级 | 错误类型 | 谁能抓到 | 定位 |
| --- | --- | --- | --- |
| L1 | 语法错误 | lint/编译 | 不做（工具秒抓） |
| L2 | 单周期功能错误 | 仿真 tb | 不为主（竞争饱和） |
| L3 | **跨周期行为错误**（状态跳转/握手/FIFO 满空/边界回绕） | 仅形式验证或极端测试 | **主攻目标** |

### 2.2 关键外部事实（2025–2026）
- ChipAgents RCA 商业落地（定位 3 周期竞争条件，调试天级→分钟级）——痛点被工业验证；
- FVDebug（NVIDIA 2025-09）：反例→因果图→根因→修复，依赖商业工具、无消融、无充分性量化；
- 开源反例引导 pipeline（arXiv 2607.28877）：同工具链但 6 benchmark 仅 1 个可靠修复——**开源链路成功率低是真实空白**；
- CVDP：盲目套 Agent 框架反而变差；HDL-FixBench 因规模/多样性/污染被 ICLR 2026 拒稿。

## 3. 核心论点与差异化

> **Thesis**：综合前验证的真正难点是"测试通过但形式失败"的**跨周期行为缺陷**。以形式反例为最高置信证据，构建"结构化证据（B 主设置）→ 充分性闭环（形式再验证）→ 切片约束修复"主线，C 反例语义化作为可解释性探索，并系统量化不同证据表示（A 原始日志 / B 结构化 / C 反例语义化）对定位与修复的增量。

**差异化三支柱**：① 开源全链路可复现（无商业工具依赖）；② 三设置消融方法论（FVDebug 等均未做）；③ 跨周期专项 + 验证充分性量化（mutation/非空洞/假阳性率）。

**边界声明**：与传统 CEGAR/反例诊断（布尔推理、无语义解释）不同；与断言生成工作（ChatSVA/AssertLLM 生成断言，我们消费反例）方向互补；与 2607.28877（原始反例直喂 LLM）差在反例语义化层。

### 3.1 最新 AI 技术结合点
| # | 结合点 | 位置 | 收益 |
| --- | --- | --- | --- |
| T1 | 多模态波形图理解（**探索章节**） | CexSemantizer 视觉通道：VCD→波形图→多模态摘要 | 视觉通道是 FVDebug 未覆盖的；预研不佳仍保留 |
| T2 | Prover–Verifier 多智能体 | Verifier 增加独立验证 agent，防自证自洽 | 强化可审计性；补丁质量消融 |
| T4 | MCP 工具层 + Reasoning 模型 | Controller 工具注册/轨迹记录标准化 | 工程底座、可复现 |

## 6. 核心组件详细设计

### 6.1 EvidenceEngine
解析 4 类输入（编译/lint/仿真断言失败/sby 反例）→ 统一 JSON；正则优先覆盖 80%；**X 态归一化**（统计含 x/z 信号并告警降权）。
```json
{"schema_ver":"v1.0","evidence_source":"sby_bmc","error_type":"state_jump",
 "module":"fifo_sync","file":"rtl/buggy.v","line":42,"code_slice":"always ... 42-48",
 "signals":{"clk":"input","wr_en":"input"},"trigger_condition":"...","fail_stage":"bmc_depth_10",
 "x_state_warn":false,"raw_trace_ref":"samples/s01/cex_trace.vcd"}
```

### 6.2 CexSemantizer（核心）
- **周期切分**：以 clk 上升沿切分 VCD 变化序列为周期事件表：
```python
for ch in vcd.changes:
    if ch.sig == clk_sig and ch.val == 1:   # 上升沿
        cur_cycle += 1
    events.append({"cycle": cur_cycle, "sig": ch.sig, "val": fmt(ch.val)})
```
- **状态轨迹**：只保留状态/关键控制信号（状态寄存器、指针、计数器、valid/ready/full/empty），逐周期表；
- **故障锥**：以断言违例信号为根，沿组合/时序依赖反向提取相关信号（静态近似，不引入 SAT）；
- **NL 摘要**：M3 基于上述数据生成 3–5 句摘要（模板见附录 A）；
- **T1 视觉通道**：VCD→波形图（gtkwave 批处理/自绘 SVG）→M3 多模态提取→与文本通道融合（文本优先）。

### 6.3 LocalRepairer
- **切片约束（状态相关域）**：故障锥信号所在 always 块 + 直接赋值链（≤10 行/块）；只允许修改切片内代码，禁改接口；
- **Prompt 模板族**（A/B/C/D 共用，仅证据段替换）：系统提示 + 证据段 + 切片代码 + 约束段（三通过判据、diff 格式）+ 一行修改意图；
- **diff 校验**：应用 diff → iverilog 语法检查 → 失败重试 ≤2 次。

### 6.4 Verifier
- **三通过判据（修复成功）**：① iverilog 编译 0 error；② 弱 tb 回归全绿；③ sby bmc -k 15 且（k-induction 证明 或 bmc 覆盖 bug 深度+2）；
- **断言子集（候选，Gate-1 实测收敛，仿真侧 `$fatal` 双实现）**：

| 语法 | iverilog 12 | yosys -formal | 备注 |
| --- | --- | --- | --- |
| `assert (expr);` immediate | ✓ | ✓ | 基础 |
| `assume (expr);` | ✓ | ✓ | 环境约束 |
| `assert property (@(posedge clk) a);` | ✓ | ✓(部分) | 单信号 |
| `$rose/$fell/$past` | ✓ | 待实测 | 时序原语 |
| `|->` / `##1` 简单 sequence | 部分 | 待实测 | 高风险项 |
- **mutation 注入器**：6 类（改运算符/翻转条件/去 reset/改位宽/改状态编码/去 else）；断言应杀死 ≥80% 变异体；
- **vacuity 近似**：断言翻转 mutation（P→¬P 仍形式通过则 P 空洞）；统计反例中实际触发断言占比；取反变异必须用强变异（==<->!= 等），且 PASS 需区分"前提不可达/门控冗余"与"真实断言无效"；
- **修复前后假阳性率**：L2 样本上"误报为 L3"比例，量化纯度门禁代价；
- **T2 验证 agent**：M3 独立审查 patch（无关修改/接口变更/证据闭环），不通过回灌 ≤1 轮。

### 6.5 Controller（实验变量）
固定流水线 vs 规则调度（按 error_type 选验证深度）vs LLM 调度三档；T4 MCP 风格工具 `compile/sim/lint/formal/query_cex` 注册，动作全记录。

### 6.6 BugBench-PS（资产）
- **6 模块**（含 2 协议类）：fifo_sync / uart_tx / uart_rx / axi_lite_slave / fsm_ctrl / counter_alu；
- **错误类型矩阵**（7 类）：状态跳转/握手/FIFO 满空/边界回绕/复位/位宽截断/边沿；每模块 5–7 注入点；
- **7 件套**：golden / buggy / 断言 / 弱 tb / 反例(vcd+日志) / schema JSON / 说明；
- **构造流程**：黄金设计 → 注入器生成变体 → 自动校验"compile ✓ → sim ✓（弱 tb 放过）→ formal ✗"→ 判 L3；不满足丢弃或调 tb；
- **污染检查**：记录构造日期与来源；声明常见教学模块污染风险 + 多样性矩阵缓解；
- **防拒稿条款**（HDL-FixBench 教训）：规模 ≥30、错误类型多样性 ≥5、patch 阈值口径、非 LLM 基线、工具版本锁定。

## 8. 评测方案
**指标**：定位 Top-1/3、修复三通过率、patch 质量（行数/无关修改）、验证充分性（mutation/非空洞/假阳性）、成本（token/费用/轮数/时间）、可审计性（轨迹完整率）。
**设置**：A 原始日志 ／ B 结构化 JSON（MiniMax 上定位最优，主设置）／ C 语义化 ／ D FVDebug 式因果图摘要（成本最低对照）／ T1 探索（C+视觉）。
**扩展实验（2026-08-05 完成）**：跨模型重跑（DeepSeek v4-flash，A/B/C×34×3-seed=306 次，BMC 统一判据严格配对）验证证据表征×模型交互效应（B 优势模型依赖）；L2 门禁对照（24 样本×A/B/C=72 次）量化假阳性率（91.7%）。
**统计**：n≥20，3 随机种子均值±方差，McNemar 配对显著性；跨模型对比限定三-seed 严格配对（306 对）。
**失败模式分析**（2607.28877 框架）：bounded-cover vacuity / spec ambiguity / temporal-logic / multi-property pressure 四类分类。

## 9. 实验协议（防偏）

### 12.3 TOP 难点
1. **C vs B 增益**（极高，Gate-0 前移控制）；2. **断言子集兼容**（高，Gate-1）；3. **L3 样本稳定**（高，注入器自动校验）；4. **vacuity 近似**（高，明示近似+交叉验证）；5. **与 FVDebug 对比**（高，method replication 声明）；6. **3 个月压力**（高，并行+自动化）。

### 12.4 总体结论
技术实现难度**中**（无原理性未知，全是确定性工程）；科研不确定性**高**（C vs B 一个变量，已用 Gate-0 前移 + 双叙事预案对冲）；时间压力**高**（靠并行+自动化化解）；外部依赖**低-中**。**可做**：不确定性已前移（两个最大变量 W3 前验证）、最大工作量可脚本化无人值守、降级路径清晰（Gate-0 不通过切稳妥叙事不返工）。

## 13. 创新价值与实用价值评估
- **创新价值：中等**（Gate-0 通过后可达中高）。单点"反例语义化"被 FVDebug 抢先（低-中），靠三支柱组合支撑：三设置消融（中-高）、充分性量化接入修复闭环（中）、T1 视觉通道（FVDebug 未覆盖，中）、跨周期数据集（中）。
- **实用价值：中高**。痛点被工业验证（ChipAgents/FVDebug）；全开源低成本可复现（相对商业差异化）；评测资产可复用；局限=教学级模块初版、工业协议扩展待 M6。
- **成败关键**：M0.5 预研（C 相对 B 增益 + T1 快测）决定主叙事是"反例语义化驱动"（高分）还是"证据工程+充分性闭环"（稳妥）。

## 16. v2.0 详细设计（Phase A/B 落地规格，2026-08-05）

> 本章将 §15 的 A（快赢：自适应 BMC + 多候选仲裁）与 B（定位：TraceAnalyzer + 反例差分诊断）细化到可直接开工的规格；C（顶层审计）/ D（结构模板）在 A/B 落地后按相同粒度补写。

### 16.1 目标管线（v2.0）

```text
失败反例 (sby cex.vcd)
  → [EvidenceEngine] schema JSON
  → [CexSemantizer v2] 周期事件/状态轨迹 + 动态切片（新增）
      ├─ TraceAnalyzer：golden-vs-buggy 同激励对比 → 首次异常周期 first_anomaly
      ├─ 恒定错误值检测：应翻转未翻转信号集 stuck_signals
      └─ 时序依赖图：断言违例信号 ← 驱动链 ← 状态/条件（≤3 层）
  → [Repairer v2] 修复意图 JSON + PatchAssembler
      ├─ 意图：{action: split_state|insert_wait|guard_boundary|edit_assign, target, params}
      ├─ 确定性生成 patch；LLM 直写 diff 降为 fallback
      └─ 多候选：同一证据 3 候选 × temperature {0.2,0.5,0.8}
  → [Verifier v2] golden-first 四通过
      ├─ ① 编译 0 error
      ├─ ② 弱 tb 回归全绿
      ├─ ③ 自适应 BMC：depth 递增序列，覆盖 bug_depth+2
      └─ ④ 顶层审计：接口签名 + SoC 回归（Phase C 起纳入）
  → [CandidateRanker] score = w1·depth_ratio + w2·(1-lines/max_lines) + w3·top_audit
  → 全失败时 [FeedbackGenerator] 新旧 cex 差分 → 诊断注入下一轮 prompt
```

### 16.2 自适应 BMC 协议（WP1）

- **golden-first 不变**：golden 必须以与修复后相同的深度协议 PASS，否则判据无效（延续 v1.6 判据一致性教训）。
- **深度序列**：ceil(bug_depth × 1.5) → ×2 → ×4（默认上限 4×bug_depth，每级超时 3min，8 并发）。
- **输出**：max_passed_depth / verdict / elapsed 三列，覆盖全 306 补丁。
- **判定**：修复成功需 max_passed_depth ≥ bug_depth+2 且 golden 同深度 PASS；否则标记 LIMITED 并纳入充分性缺口报告。
- **论文口径**：修复率（深度覆盖达标）+ LIMITED 占比双报告，取代单一“有限深度 BMC 通过”。

### 16.3 多候选仲裁（WP5）

- 同一 (sample, setting, seed) 生成 3 候选，temperature 0.2 / 0.5 / 0.8；首次 prompt 口径与旧协议逐字节一致，仅新增候选维度。
- 各候选独立验证；仲裁分 score = 0.5·(max_depth_ratio) + 0.3·(1 − patch_lines/max_lines) + 0.2·top_audit_pass。
- 任一候选通过即记 repair_pass，并记录通过候选的 temperature 与名次；全部失败才触发 FeedbackGenerator。
- **代价**：LLM 调用 ×3（DeepSeek flash 单价低，预算不限）；验证 ×3 但 8 并发下墙钟增量可控。

### 16.4 TraceAnalyzer（WP2）

- **输入**：buggy cex.vcd + golden.v 同激励仿真 VCD。
- **输出**：{first_anomaly_cycle, key_signal_diffs[], stuck_signals[], driver_chain[]}。
- **算法**：
  1. 时钟对齐，逐周期比对 golden/buggy 关键信号 → first_anomaly_cycle；
  2. stuck_signals：断言窗口内值不变但 golden 翻转的信号（恒定错误值检测）；
  3. driver_chain：从断言违例信号沿赋值语句反查（组合+时序），取 ≤3 层。
- **预期收益**：直接打击定位最弱项（状态跳转 36.1%、握手 27.8%），驱动 B 定位 top-1 ≥72%。

### 16.5 反例差分诊断（WP6）

- 修复失败后自动重跑新 cex，与旧 cex 差分：信号变化集（新出现/消失的异常信号）、失败周期移动（前移=恶化，后移=部分修复）、状态卡死（状态寄存器连续 N 拍不变）。
- 生成 ≤120 token 诊断文本，注入下一轮 prompt（retry_history v2）。

### 16.6 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 多候选 ×3 使 LLM 成本 ×3 | DeepSeek flash 单价低；仲裁后仅记录通过候选；预算不限 |
| 自适应深度上限内仍不够 | LIMITED 标记 + 充分性缺口报告，论文如实呈现 |
| PatchAssembler 模板匹配失败 | LLM diff fallback；模板先覆盖 7 类错误中的 3 类高频 |
| 顶层审计引入新失败 | 如实入论文（接口签名不一致率），视为新发现而非缺陷 |

### 16.7 阶段依赖

C 依赖 A（验证管线先就绪）；D 依赖 B（结构性修复需要动态切片定位）。顺序 A→B→C→D，A 与 B 无强依赖可部分并行。

### 17.1 Phase C：顶层互联审计（WP4）

- **目标**：验证“模块内 BMC 通过但改变外部行为”的风险，接口签名一致率成为第四通过判据。
- **三层做法**：
  1. **接口行为签名**：对 golden 与修复后 RTL 施加同一激励序列，逐周期比对输出波形（wr/rd 握手、valid/ready、fifo full/empty、uart tx/rx 帧、axi 通道握手）；
  2. **小型 SoC 回归**：6 模块组装一个 SoC 测试台（fifo↔uart↔axi↔fsm↔counter），跑代表性事务，比较 golden 与修复后输出；
  3. **顶层协议断言**：基于模块间协议自动生成断言（握手顺序、FIFO 满空、AXI 响应），随 SoC 回归一起跑 sby。
- **数据**：306 全量接口签名一致率报告；不一致即如实入论文（视为新发现）。
- **依赖**：A（验证管线就绪）+ B（定位质量提升后修复更可信）。

### 17.2 Phase D：结构性重写模板（WP3）

- **三模板起步**（对应 7 类错误中高频难修项）：
  1. **状态拆分 split_state**：复合状态拆多个子状态（状态跳转类）；
  2. **握手等待态 insert_wait**：状态转移中插入等待/确认态（握手类）；
  3. **边界守卫 guard_boundary**：增加位宽/深度/边界判断（边界回绕/位宽截断类）。
- **流程**：LLM 输出修复意图 JSON → PatchAssembler 确定性生成补丁 → 三通过 + 顶层审计；意图匹配失败降级为 LLM 直写 diff。
- **样本**：新增 5–10 个结构性缺陷样本（注入器扩展 structural 模板），验证结构性修复率 ≥80%。
