## 2. 并行度验证（关键证据）

- 8 个分片日志（exp8_part_0..7.json.log）各自从 run 1 顺序编号到末尾（seq=True），样本互不重叠（按 34 样本均分）。
- token 账本中 8 个主会话（session 前缀 20260804005315/…）的调用**在时间线上交错出现**：
  00:53:29 cb67f5 → 00:53:39 b1095b → 00:53:47 4ba9c3 → … 8 会话全部在 00:53-00:56 启动并轮番出账。
- 8 会话跨度：50.4 / 83.0 / 93.0 / 115.4 / 165.2 / 181.0 / 183.9 / 184.1 分钟 → **关键路径 ~184 分钟 ≈ 3.1 小时**，
  加启动/收尾 ≈ 3.5 小时。**并行真实成立**，之前任何"串行"猜测均不成立。

## 3. 成本与 Token 效率（效果评估：达标）

| 设置 | 任务数 | 总 tokens | 总成本(USD) | 单任务中位成本 | loc_top1 | repair |

| A 原始日志 | 102 | 1,977,971 | 2.751 | ~0.024 | 46.1% | 73.5% |
| B 结构化证据 | 102 | 1,753,835 | 2.705 | ~0.023 | **61.8%** | 73.5% |

- **B 性价比最优**：tokens 最少、cost 最低、loc_top1 最高（61.8%），是 Gate-0 叙事修正为 B 主设置的量化依据。
- **C 成本超标**：semantics.json 是 evidence.json 的 10-36 倍大（中位 22.5 倍），tokens/成本最高但修复率无增益。
- 账本一致性：306 条结果求和成本 $9.6116，与账本 exp: 标签合计一致（约 $9.6，其余为 cex_semantize/预研/T1 等）。

## 4. 瓶颈定位（效果未达最优处）

1. **验证环节（prove/k-induction + BMC）不在 token 账本内**，是墙钟大头：
   - axi（s17）prove 单次 5-10 min；uart_rx 深时序 BMC depth 176+ 收敛慢；
   - 慢样本（s17/s34/s25/s36）的验证重试多次，导致分片墙钟远超 LLM 段。
2. **重试策略偏保守**：avg_attempts axi=3.0（全满 3 次）、uart_rx=2.22、uart_tx=1.81；
   39 次 llm_fail（网络/超时）+ 126 次 diff_apply_fail + 176 次 verdict-fail 均触发重试。
   - 其中 126 次 diff_apply_fail 中 10 条离线重放转 PASS（diff 应用器模糊匹配修复后），29 条真实失败；
   - **改进空间**：diff 应用失败可先本地重试（已实现模糊匹配），LLM 网络失败可降级重试间隔。
3. **C 语义化 token 过大**：s34/C 单任务 $0.2457（9 次调用），s17/C $0.1769（5 次），远超中位；
   - 已做 window 压缩（预研 s03 -55%），主实验语义化仍偏高 → 可复用压缩配置重生成 C 证据。
4. **增量断点续跑已生效**：partial.jsonl 存在且 merge 后 306 条完整（missing=0），失败重放/补跑管线闭环。

## 5. 提速建议（按 ROI 排序）

1. **验证并行化**：evaluator 的 compile/sim/prove 已按任务并行（8 进程），但单任务内验证串行；
   对 axi/uart 可尝试 prove 超时上限（如 600s→300s）+ BMC depth 参数化，避免长尾。
2. **按成本/耗时均衡分片**：改为按"样本×设置"粒度 + 已知慢样本分散（s17/s34/s25/s36 各分一片）。
3. **重试预算化**：diff_apply_fail 本地重试（零成本）优先；LLM 网络失败指数退避上限 20s；
   全任务 attempts≥3 且 verdict=fail 的样本可标记"难度天花板"不再重试。
4. **C 证据压缩复用**：semantics.json 生成启用 --window（预研已验证 -55% token、-55% 成本）。
5. **账本补充验证段计时**：token_ledger 仅记 LLM；建议 evaluator 侧落 prove/BMC 耗时（本次审查为此需从日志推断）。
