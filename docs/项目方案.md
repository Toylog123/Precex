> 项目名：PreCex（Pre-synthesis + Counterexample）
> 数据集名：BugBench-PS

> 作者：Toylog
> 版本：v1.4（2026-08-03，基于可做性审查：3 个月硬时间线 + 自动化模式）
> 状态：待评审
> 说明：v1.4 依据"可做性审查"更新：① 3 个月硬性交付约束，里程碑压缩为周级并行计划；② 单人 + 智能体全程协助的运行模式，数据集与评测全部自动化管线化；③ T1（波形图视觉）降级为探索章节（预研不佳仍保留，低成本呈现）；④ LLM 定案 MiniMax M3 API（预算不限）。v1.3 的 T2/T4 保留。

## 1. 背景与问题

综合前验证的失败证据按"发现难度"可分为三个层级：

| 层级 | 错误类型 | 谁能抓到 | 现状 |
| --- | --- | --- | --- |
| L1 | 语法错误 | lint / 编译 | 工具秒抓，LLM 无研究价值 |
| L2 | 单周期功能错误 | 仿真 testbench | LLM 修复竞争饱和（RTLFixer、VeriDebug、VeriPilot 等） |
| L3 | **跨周期行为错误**（状态跳转、握手协议、FIFO 满空、边界回绕） | 仅形式验证或极端测试 | **"测试通过但形式失败"假阳性普遍，是综合前验证的真正难点** |

关键外部事实（2025–2026 文献）：

- 工业界已确认该痛点的价值：ChipAgents RCA 商业落地，能定位"3 周期竞争条件"类缺陷，调试周期从天级压缩到分钟级；
- FVDebug（NVIDIA, 2025-09）已做"反例→因果图→根因→修复"，依赖商业工具且无消融、无验证充分性量化；
- 开源反例引导 pipeline（arXiv 2607.28877, 2026-07）与本文工具链一致，但 6 benchmark 仅 1 个可靠修复——**开源链路成功率低是真实空白**；
- CVDP 警示"盲目套 Agent 框架反而变差"；HDL-FixBench 因规模/多样性/污染问题被 ICLR 2026 拒稿。

## 2. 核心论点（Thesis）与差异化

> 综合前验证的真正难点是"测试通过但形式失败"的**跨周期行为缺陷**。以**形式反例**作为最高置信证据源，构建"结构化证据 → 反例语义化 → 切片约束修复 → 形式再验证"的闭环智能体，并在**开源全链路**上系统量化不同证据表示（原始日志 / 结构化 / 反例语义化）对定位与修复的增量价值。

**差异化三支柱**（相对 FVDebug / GROVE / 2607.28877）：
1. **开源全链路可复现**：iverilog + verilator + yosys + SymbiYosys，无商业工具依赖（FVDebug 依赖商业 FV 工具）；
2. **三设置消融方法论**：A 原始日志 / B 结构化证据 / C 反例语义化，量化"证据表示"本身的科学贡献（FVDebug 等均未做）；
3. **跨周期 bug 专项 + 验证充分性量化**：mutation score、断言非空洞率、修复前后假阳性率（FVDebug 未涉及）。

**与已有工作的边界声明**：
- 传统 counterexample-guided debugging（CEGAR/反例诊断）：做布尔/符号推理，输出最小冲突集合，不产出语义解释与修复意图；
- Agentic Coverage Closure / ChatSVA / AssertLLM：**生成断言**去捕获 bug；本方案**消费反例**去修复 bug，方向互补；
- 2607.28877：同工具链但把原始反例直接喂 LLM；本方案增加**反例语义化层**并量化其增量。

### 2.1 与最新 AI 技术的结合点（v1.3 新增）

| # | 结合点 | 技术依据 | 结合方式 | 创新价值增益 |
| --- | --- | --- | --- | --- |
| T1 | **多模态波形图理解**（**探索章节**） | PostEDA-Bench 证 vision 增益；ChatSVA 处理波形图；FVDebug 用波形但**未用视觉图像通道** | 反例 VCD → 渲染波形图 → 多模态 LLM 视觉通道分析关键信号变化，与结构化轨迹融合进 CexSemantizer；**预研不佳仍保留为论文探索章节** | 反例语义化新颖性 低-中 → **中**（视觉通道是 FVDebug 未覆盖的） |

| T4 | **MCP 工具层 + Reasoning 模型** | MCP 已成 agent 工具标准；reasoning 模型在复杂多跳定位更强 | Controller 工具注册/轨迹记录用 MCP 风格接口；LLM 默认选 reasoning 类模型增强反例分析质量 | 工程可落地性、可审计性；模型选型建议（见 10 待确认项） |

选择原则：只选与"工具裁决、证据驱动"哲学契合的技术。T1/T2 为主路径必选；T3 为可选加分项（算力敏感）；T4 为工程底座。

### 3.2 数据可行度
- **L3 样本构造法明确**：强断言 + 弱 testbench；buggy 版过 tb + 败 formal（与 AssertLLM2 bug-hunting、LintLLM mutation 注入同构，有方法学先例）；
- **质量门禁**：每样本标注检测层级；主实验只用 L3；
- **规模**：目标 30–40 个 L3 样本（吸收 HDL-FixBench 拒稿教训：规模与多样性是评审硬门槛）。

### 3.3 实验可行度
- A→B 增益已有文献支持；**B→C 是风险集中点**（FVDebug 未证明该增量）→ 用 L3 纯度门禁 + **M0.5 三例预研**先行验证；
- T1（视觉通道）作为 C 的增强子实验（C 与 C+vision 对比），不改变主实验骨架；
- 变量受控：同一 LLM、同一 prompt 模板族，仅证据表示不同。

### 3.4 论文可行度
- 定位：形式验证与 LLM 交叉（FMCAD/DAC/ICCAD/TCAD），或验证期刊（TCAD/TVLSI）；
- 竞争环境：FVDebug/GROVE 已先行，**审稿人必要求对比** → 论文必须含"因果图摘要"对照设置 D（详见 9.3）与三支柱差异化；
- T1/T2 提供额外差异化弹药；T3（RLVR）已不做，写入 future work。

### 3.5 资源需求
- 计算：sby bmc 分钟级，单机完成主路径；T3 已不做，无训练算力需求；
- 外部依赖：仅 LLM API（MiniMax M3，已确认可用、预算不限）；其余全开源；
- 人力与时间：**3 个月硬约束**（单人 + 智能体持续推进）；人力资源集中于 W4–W7 数据集构建与解析器，靠自动化管线降低人工介入。

### 4.2 实用价值：**中高**
- **问题真实且被工业验证**：ChipAgents RCA 商业落地、FVDebug 获 NVIDIA 工业反例背书；
- **全开源、低成本、可复现**：相对商业方案（FVDebug/ChipAgents）差异化明确；

## 7. 关键组件设计

- **EvidenceEngine**：输入 iverilog 错误 / verilator lint / 仿真断言失败 / sby 反例 → 输出统一 JSON（error_type/file/line/code_slice/signals/trigger_condition/fail_stage）；正则优先，覆盖 80% 常见格式。
- **CexSemantizer（T1）**：双通道——①解析通道：反例波形→时钟周期切分→状态轨迹→与断言比对→结构化摘要；②视觉通道：VCD 渲染波形图（gtkwave/自绘 SVG）→ 多模态 LLM 提取关键信号变化；两通道输出融合后进 LLM 修复上下文。
- **LocalRepairer**：约束 prompt 只输出 diff；iverilog 语法校验后落盘。
- **Verifier（T2）**：工具裁决层（iverilog + sby；mutation 注入器；断言子集限定 iverilog12 与 yosys `-formal` 兼容子集 + 仿真侧 `$fatal` 双实现）+ 独立验证 agent（审查 patch 是否引入无关修改、证据是否闭环）。
- **Controller（T4）**：MCP 风格工具注册（compile/sim/lint/formal 可插拔）；固定流水线基线 vs 规则/LLM 选择 A/B；轨迹全记录。
- **BugBench-PS**：6 模块 × 5–7 错误 ≈ 30–40 L3 样本；每样本 7 件套；自动校验（Rule2DRC 式工具裁决）。

## 8. 数据集设计（吸收 HDL-FixBench 拒稿教训）

1. **规模与多样性**：L3 样本目标 30–40；错误类型覆盖 ≥5 类（状态跳转/握手保持/FIFO 满空/边界回绕/位宽/复位）；按"模块×错误类型"矩阵标注；
2. **污染检查**：样本标注数据来源与构造日期，规避常见模块被 LLM 训练语料污染的评估偏差；
3. **非 LLM 基线**：补纯规则/无工具裁决的基线，防"评估设置缺失"争议；
4. **patch 阈值**：明确定义"修复成功"（三通过：compile/sim/formal）与补丁大小统计口径；
5. **可复现**：容器化或脚本化工具环境，版本锁定记录。

## 9. 评测方案

指标沿用 6 条评估主线（定位 Top-1/3、修复三通过、补丁质量、验证充分性、成本、可审计性）。

### 9.1 主实验（仅 L3，n≥20，目标 30–40）
- A：原始日志文本回填（基线）
- B：EvidenceEngine 结构化证据
- C：结构化证据 + CexSemantizer 反例语义化（主方案）
- **D（新增）：FVDebug 式因果图摘要**（反例→信号依赖 DAG 摘要喂 LLM，验证 C 相对既有方案的增量）
- **C+vision（T1 子实验）：C + 多模态波形图通道**（验证视觉通道增量）

### 9.2 消融与辅助实验
- 切片约束 vs 全文件重写；固定流水线 vs Controller；
- T2 验证 agent 开/关（补丁质量、无关修改比例对比）；
- 断言有效性：非空洞率、mutation score、修复前后假阳性率。

### 9.3 失败模式分析（采用 2607.28877 框架）
按 4 类分类统计修复失败：bounded-cover vacuity / spec ambiguity / temporal-logic / multi-property pressure；为论文"失败分析"章节提供结构性证据。
