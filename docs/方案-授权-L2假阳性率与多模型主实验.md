## 方案 A：L2 假阳性率量化

### 背景与目标
- L2 = 单周期功能错误（仿真 tb 可抓，弱 tb 失败），非本项目主攻（L3 = 弱 tb 过 + 形式验证失败）。
- 假阳性率定义：**弱 tb 能抓但 formal 也失败的"伪 L3"比例**——即被系统误判为 L3 的样本占 L2 样本的比例。
- 当前缺口：**零 L2 样本，无数据源，不能编造**（进度.md 已记录，等用户决策）。

### 采样设计（待授权）
1. 数量：6 模块 × 每模块 4 个 L2 样本 = **24 个 L2 样本**（与 L3 的 34 样本量级相称；成本/时间可控）
2. 错误类型：每模块选 2 类**单周期可观测**错误（如位宽截断立即溢出、组合逻辑错误、复位立即错误、单周期握手错误）——排除跨周期类（状态跳转/边界回绕属 L3）
3. 生成方式：复用 scripts/bug_injector.py，新增 `--level L2` 注入模式（弱 tb 直接 FAIL，无需 formal 反例）
4. 数据目录：`samples/l2/<sid>/`（新目录，红线，须授权）
5. 验证：每样本过"弱 tb FAIL + formal 抓反例"双检，判定是否伪 L3

### 执行步骤（授权后）
1. bug_injector.py 加 L2 注入模板（改注入点使弱 tb 断言失效）
2. 生成 24 样本 → 三通过校验（弱 tb FAIL 预期）
3. 主实验管线 A/B/C/D 各跑 1 seed（24×4=96 次 LLM 调用）→ 统计"被系统修复且三通过"的比例
4. 假阳性率 = 系统把 L2 当 L3 修好（误报）的比例；与 L3 修复率对比，量化纯度门禁代价
5. 结果写入 docs/进度.md + 论文局限性（如获批）

### 预算/风险
- LLM 成本：96 次调用 ≈ MiniMax 主实验 $2.7~4.2 的量级（预计 <$5）
- 风险：L2 样本若弱 tb 已 FAIL，系统"修复"语义不同（仿真级修复 vs 形式级），需明确指标口径；若用户不授权，则以"无 L2 样本、假阳性率留待后续"诚实披露

## 方案 B：多模型主实验（DeepSeek 重跑 A/B/C）

### 背景与目标
- 当前主实验全部基于 MiniMax M3（单提供商威胁，论文 limitations 已列）。
- 用户已提供 DeepSeek key（deepseek-v4-flash），llm_client 已支持多 provider。
- 目标：用 DeepSeek 重跑主实验，量化跨模型鲁棒性（B 定位优势是否跨模型成立）。

### 实验设计（待授权）
1. 范围：A/B/C × 34 样本 × **1 seed**（不跑 3 seeds，控制成本；seed 固定 0，与 MiniMax 主实验 seed 0 可比）= 102 次调用
2. 模型：deepseek-v4-flash（非 thinking，temperature=0）
3. 判据：与 MiniMax 主实验一致（bmc 修复判据、loc_top1 行号判据）
4. 产出：DeepSeek 版 loc_top1 / 修复率 / 成本 / tokens，与 MiniMax 对照表
5. 追加（可选）：DeepSeek 版 B 证据 10 样本可解释性评分（复用 Phase 2 脚本）

### 预算/风险
- DeepSeek 成本：102 次调用 × ~$0.03 ≈ **$3-5**（flash 计价远低于 MiniMax）
- 风险：跨模型比较需同 prompt/同判据；DeepSeek 与 MiniMax 输出风格差异可能影响 diff 应用器，需预留重试
- 若用户不授权：保持单提供商，论文以"单提供商威胁"诚实披露
