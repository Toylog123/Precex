## 1. 项目概述

**一句话目标**：3 个月内（2026-08 起，2026-10 论文初稿）构建一个**以形式反例为最高置信证据源**的综合前 RTL 缺陷定位与修复智能体，产出可发表论文、BugBench-PS 数据集与开源工具链。

**核心命题**：综合前验证的真正难点是"测试通过但形式失败"的**跨周期行为缺陷**（L3）。以形式反例驱动"结构化证据 → 反例语义化 → 切片约束修复 → 形式再验证"闭环，并系统量化不同证据表示（A 原始日志 / B 结构化 / C 反例语义化）对定位与修复的增量。

**关键配置（已定案）**：
- LLM：MiniMax M3 API（OpenAI 兼容端点，1M 上下文，原生多模态，thinking 控制，预算不限）
- 工具链：iverilog / verilator / yosys / SymbiYosys（sby），全开源
- 时间：13 周并行里程碑；人力：单人 + 智能体自动化管线
- 差异化三支柱：开源全链路 / 三设置消融方法论 / 跨周期专项 + 验证充分性量化

## 2. 问题定义与目标场景

### 2.1 失败证据层级

| 层级 | 错误类型 | 谁抓得到 | 本项目定位 |
| --- | --- | --- | --- |
| L1 | 语法错误 | lint/编译 | 不做（工具秒抓） |
| L2 | 单周期功能错误 | 仿真 tb | 不为主（竞争饱和） |
| L3 | 跨周期行为错误 | 仅形式验证/极端测试 | **主攻目标** |

### 2.2 L3 典型场景（数据集错误类型的地基）
1. **状态跳转错误**：状态机少跳/多跳/错跳一个状态；
2. **握手协议错误**：valid/ready 的保持或 deassert 时序错误（AXI/AXI-lite 通道）；
3. **FIFO 满/空条件错误**：读写指针、计数器、full/empty 生成逻辑；
4. **边界/回绕错误**：计数器上限、位宽截断、地址回绕；
5. **复位/初始化错误**：漏复位信号、初值错误、异步复位同步释放；
6. **位宽/截断错误**：信号位宽不匹配导致的静默截断；
7. **时序/边沿错误**：posedge/negedge 错用、组合逻辑误入时序块。

### 2.3 L3 样本的可验证判据（三通过反向）
- buggy 版：**过 tb（弱 testbench）+ 败 formal（强断言）**；
- golden 版：过 tb + **过 formal**。

## 3. 技术路线总览

参考《项目方案.md》第 6 章框架图。主链：输入证据 → EvidenceEngine → CexSemantizer → LocalRepairer → Verifier → 输出；Controller 贯穿；M3 为推理内核；Gate-1/0/2 控制质量。本节以下按组件逐一展开设计。

## 4. 六大组件详细设计

### 4.1 EvidenceEngine（证据工程）

**功能**：把异构失败证据归一化为统一 JSON schema。

**输入**：
- iverilog 编译错误文本（`ERROR: ...` 行）；
- verilator lint 告警文本；
- 仿真断言失败日志（`$fatal` 或断言消息 + 时间戳）；
- sby 反例输出（引擎日志 `--  Failure: ...` + `trace.vcd` + `engine_0.trace`）。

**处理流程**：
1. 逐行正则匹配 → 提取 file/line/error_type；
2. 反例文件解析：VCD 头部（信号表）+ 变化段（时间戳 + 信号值）；
3. **X 态归一化**：统计含 `x/z` 的信号，标记"X 态污染警告"；反例语义化阶段对这些信号降权；
4. 组装 JSON。

**JSON schema（字段级）**：

```json
{
  "schema_ver": "v1.0",
  "evidence_source": "sby_bmc | sby_kinduction | sim_assert | lint | compile",
  "error_type": "state_jump | handshake | fifo_full_empty | boundary_wrap | reset | width_trunc | edge",
  "module": "fifo_sync | uart_tx | uart_rx | axi_lite_slave | fsm_ctrl | counter_alu",
  "file": "rtl/buggy.v",
  "line": 42,
  "code_slice": "always @(posedge clk) ... 42-48 行",
  "signals": {"clk": "input", "wr_en": "input", ...},
  "trigger_condition": "断言/引擎给出的违例条件",
  "fail_stage": "assert_fifo_full | bmc_depth_10 | ...",
  "x_state_warn": false,
  "raw_trace_ref": "samples/s01/cex_trace.vcd"
}
```

**实现策略**：正则 + 规则，目标覆盖 80% 常见格式；剩余 20% 交由 M3 容错解析（可选）。

### 4.2 CexSemantizer（反例语义化，核心创新）

**功能**：把形式反例变成 LLM 友好、跨周期可读的语义化证据（C 设置）。

**通道①文本通道（主）**：
1. **周期切分**：以时钟上升沿为边界，把 VCD 变化序列切成周期事件表：

```
伪代码：cycle_split(vcd, clk_sig)
  events = []
  cur_cycle = 0
  for change in vcd.changes:
      if change.sig == clk_sig and change.val == 1:   # 上升沿
          cur_cycle += 1
          events.append({"cycle": cur_cycle, "phase": "setup"})
      events.append({"cycle": cur_cycle, "sig": change.sig, "val": format(change.val)})
  return events
```

2. **状态轨迹提取**：只保留状态/关键控制信号（状态寄存器、指针、计数器、valid/ready、full/empty），生成逐周期状态变化序列；
3. **故障锥构造**：以断言违例信号为根，沿组合/时序依赖反向提取相关信号集合（模块级，用源码静态依赖近似，不引入 SAT 求解）；
4. **NL 摘要**：M3 基于上述结构化数据生成 3–5 句自然语言摘要（prompt 模板固定，见附录 A）。

**通道②视觉通道（T1，探索章节）**：
1. VCD → 渲染波形图（候选：gtkwave 批处理导出 PNG / 自绘 SVG）；
2. M3 多模态（`image_url`）提取关键信号变化描述；
3. 与通道①结果融合（去重 + 冲突仲裁：文本通道优先）。

**输出（C 设置喂给修复器的内容）**：
- 周期事件表（JSON/文本）；
- 状态轨迹（逐周期表）；
- 故障锥信号清单；
- NL 摘要；
- （可选）波形图路径与视觉摘要。

### 4.3 LocalRepairer（局部修复）

**功能**：基于语义化证据 C，产出受约束的最小 patch。

**切片约束定义（状态相关域）**：跨周期 bug 常跨 2–3 个 always 块 + 状态寄存器。切片 = 故障锥信号所在的 always 块 + 直接赋值链（≤10 行/块）。约束 prompt：只允许修改切片内代码，禁止无关重构。

**Prompt 模板（固定，A/B/C/D 共用同一模板族，仅证据段落替换）**：
1. 系统提示：你是资深 RTL 验证与修复工程师，只输出合法 Verilog diff；
2. 证据段：A=原始日志文本；B=schema JSON；C=语义化（4.2 输出）；D=因果图摘要（信号依赖 DAG）；
3. 代码段：切片内代码 + 模块接口声明（顶层签名，防止改接口）；
4. 约束段：三通过判据说明、输出格式（统一 diff 标记）；
5. 输出：`diff` 块 + 一行修改意图。

**diff 校验**：解析 diff → 应用到 buggy.v → iverilog 语法检查 → 失败则返回错误让 M3 重试（≤2 次）。

### 4.4 Verifier（验证与充分性）

**功能**：工具裁决 + 验证充分性量化 + T2 独立验证 agent。

**① 三通过判据（修复成功定义）**：
1. `iverilog` 编译通过（0 error）；
2. 回归仿真通过（弱 tb 全绿）；
3. 形式验证通过：sby `bmc -k 15` 且（`k-induction` 证明 或 bmc 深度覆盖到 bug 触发深度+2）。判据严格性在论文中明示。

**② 断言子集（候选清单，Gate-1 实测收敛）**：
| 语法 | iverilog 12 | yosys -formal | 备注 |
| --- | --- | --- | --- |
| `assert (expr);`（immediate） | ✓ | ✓ | 基础 |
| `assume (expr);` | ✓ | ✓ | 环境约束 |
| `assert property (@(posedge clk) a);` | ✓ | ✓（部分） | 单信号 |
| `$rose / $fell / $past` | ✓ | 需实测 | 时序原语 |
| `|->` / `##1` 简单 sequence | 部分 | 需实测 | **高风险项** |
| `cover property` | ✓ | 不用于判据 | 覆盖统计 |

原则：**仿真侧用 `$fatal` 双实现**；不确定语法在 Gate-1 逐条实测，最终子集 = 双工具交集。

**③ mutation 注入器（充分性量化）**：对 golden 设计注入 6 类 mutation（改运算符 / 翻转条件 / 去 reset / 改位宽 / 改状态编码 / 去 else），断言集应能形式验证杀死 ≥80% 变异体（mutation score），否则断言偏弱。

**④ vacuity（非空洞）近似**：将断言 P 替换为其否定式 mutation，若形式验证仍通过 → P 空洞/弱；统计"反例中实际触发的断言占比"作为补充。

**⑤ 修复前后假阳性率**：对 L2 样本（非 L3）记录"误报为 L3 缺陷"比例，量化 L3 纯度门禁的代价。

**⑥ T2 独立验证 agent**：M3 独立审查 patch（不共享修复上下文）：是否引入无关修改、是否改变模块接口、证据是否闭环；输出通过/不通过 + 理由；不通过则回灌修复器（≤1 轮）。

### 4.5 Controller（验证规划）

**功能**：按 token/时间预算调度工具与组件，消融项。

**三档基线**：
- 固定流水线（编译→仿真→形式→修复→再验证，不做选择）；
- 规则调度（按 error_type 选择验证深度：如 handshake 类必跑 sby bmc）；
- LLM 调度（M3 选择下一步动作）。

**T4 MCP 风格工具层**：`compile / sim / lint / formal / query_cex` 注册为可插拔工具，动作与结果全记录（轨迹 JSONL），支撑可审计性指标与论文复现。

### 4.6 BugBench-PS（数据集）

**模块清单（6 模块，含 2 个真实协议类）**：
1. `fifo_sync`（同步 FIFO，full/empty/半满）；
2. `uart_tx`（UART 发射，帧格式 + 波特率分频）；
3. `uart_rx`（UART 接收，起始位检测 + 采样）；
4. `axi_lite_slave`（AXI4-Lite 从机，写/读通道握手 + 地址译码）；
5. `fsm_ctrl`（状态机控制器：定时器/模式选择/序列检测）；
6. `counter_alu`（带使能/复位的计数与简单 ALU 流水）。

**错误类型矩阵（7 类 × 6 模块，每模块取 5–7 个注入点）**：见 2.2。目标 30–40 个 L3 样本。

**注入与校验流程（自动化）**：
1. 黄金 RTL + 黄金 tb + 强断言（每个模块一组核心断言）；
2. 注入器按错误类型矩阵生成 buggy 变体（每个变体 = 一处缺陷）；
3. 自动校验三通过层级：compile ✓ → sim ✓（弱 tb 放过）→ formal ✗（sby 出反例）→ 判定 L3；
4. 不满足层级要求的变体丢弃或调整 tb 强度；
5. 生成 7 件套：golden / buggy / 断言 / tb（弱）/ 反例（vcd+日志）/ schema JSON / 说明（错误类型+注入点）。

**污染检查**：每样本记录构造日期与来源；对常见教学模块（FIFO/计数器）在论文中声明污染风险并说明缓解（构造变异体 + 多样性矩阵）。

## 6. 评测方案

### 6.1 指标定义
| 指标 | 定义 |
| --- | --- |
| 定位 Top-1 / Top-3 | 修复对话中首次触及缺陷行的轮次命中率（Top-1/3） |
| 修复三通过率 | compile + sim + formal 全部通过的样本占比 |
| patch 质量 | patch 行数、无关修改比例（T2 验证 agent 判定） |
| 验证充分性 | mutation score、断言非空洞率、修复前后假阳性率 |
| 成本 | token 数、API 费用、轮数、墙钟时间 |
| 可审计性 | 轨迹完整率（JSONL 全记录） |

### 6.2 实验设置
- **A**：原始日志文本回填（基线）；
- **B**：EvidenceEngine 结构化 JSON；
- **C**：B + CexSemantizer 语义化（主方案）；
- **D**：FVDebug 式因果图摘要（信号依赖 DAG，方法复刻对照）；
- **T1 探索**：C + 波形图视觉通道（子实验，探索章节）。

### 6.3 统计方法
- n≥20（目标 30–40）；每设置 3 个随机种子（LLM 温度>0）取均值±方差；配对显著性（McNemar 检验）标注；报告成功率与置信区间。

## 7. 实验协议（防偏与可复现）

1. 同一 prompt 模板族，仅证据段替换（A/B/C/D 严格对照）；
2. LLM 温度与重试策略固定并记录；
3. token 记账全自动化（每调用记录 in/out token、费用）；
4. 工具版本锁定（iverilog/yosys/sby 版本号入 manifest）；
5. 轨迹 JSONL 全记录，论文复现材料 = 脚本 + 数据集 + 结果表。

## 附录 A：反例语义化 NL 摘要 Prompt 模板（固定）

```
系统：你是资深 RTL 验证工程师。基于给定的周期事件表、状态轨迹与故障锥信号，
用 3–5 句中文/英文描述：缺陷发生在哪个周期、哪些信号先异常、与断言违例的因果链。
要求：不猜测证据之外的原因；指出最可疑的代码位置（模块+信号+周期）。
```
